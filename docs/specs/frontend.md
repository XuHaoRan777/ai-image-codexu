# 前端规格

## 范围

前端位于 `apps/web`，使用 React 19、Vite 8、Tailwind CSS 4 和 shadcn。当前页面是自用生图工作台，不做营销首页。

## 当前页面

### 视觉设计

前端采用暗色创作控制台风格，不做营销首页。主要视觉约定：

- 默认深色主题，背景使用低噪声网格、柔和径向光和半透明工作台面板
- 主操作使用青绿色，生成预览和重要提示使用琥珀色作为辅助强调
- 页面信息密度偏工具型，避免大面积宣传文案和装饰卡片堆叠
- 三个主页面不设置页面级标题说明区，操作反馈通过顶部全局 Toast 展示
- 主内容区外边距四向一致，避免顶部与左右边缘留白不协调
- 左侧导航包含“生图”“历史”“识图”“配置”，并展示当前模型配置数量、辅助模型状态；移动端侧栏自然堆叠到顶部
- 四个主页面使用 hash 路由保持刷新状态：`#/generate`、`#/history`、`#/recognize`、`#/settings`；未知 hash 回退到生图页
- 表单输入、选择器、预览画布和配置列表保持 8px 圆角以内，符合 shadcn 控件基础风格
- 图标统一使用 `lucide-react`，不使用 emoji 作为结构化图标
- 交互控件保留可见 focus ring、loading disabled 状态和至少 40px 以上的点击高度
- 全局动效使用短时长工具型过渡：页面切换淡入轻微位移，面板和列表项渐进入场，按钮/卡片 hover 轻微上移；必须尊重 `prefers-reduced-motion`
- 桌面端页面固定在一屏内，不使用页面级右侧滚动条；需要滚动时限制在组件内部

### 配置页

生图 provider 配置化的完整设计见 `docs/design/image-provider-config.md`。

配置页负责：

- 在模型库标题右侧通过“新增”按钮打开居中的生图模型表单 Dialog
- 新增和编辑生图模型配置，编辑时密钥留空表示不更新密钥
- 生图模型统一保存为 `providerType = configurable-http`；第三方中转商通过 HTTP 模板配置接入，不再要求后端新增独立 provider 方法
- 生图模型表单使用 Tab 组织：基础配置页维护配置名称、交付方式、模型快照、密钥和启用状态；HTTP 模板页维护请求地址、方法、Content-Type、请求头、请求体参数和返回格式；AI 配置页用于把文档地址或粘贴的接口信息交给辅助模型生成一条新配置
- HTTP 模板页使用表单草稿编辑，前端在保存前封装为 `httpConfig` JSON：请求头是键值行，请求体按提示词、尺寸比例、分辨率、数量、参考图和额外参数分组，返回格式维护图片类型、图片路径、MIME 路径和 token 路径
- HTTP 模板表单会对请求地址、提示词路径、数量范围、参考图模式、额外参数 JSON 值和返回图片路径做基础校验；校验失败时保存按钮禁用并展示错误
- 请求头、请求体参数、返回格式小标题右侧分别提供 OpenAI / Google 官方结构模板填充按钮；不展示第三方中转商快捷模板，预设只填结构，不包含真实密钥；分段模板按钮只更新对应分段，请求体参数模板不联动修改请求地址、方法、Content-Type、交付方式或模型快照
- `deliveryMode = polling` 时 HTTP 模板页显示轮询配置表单，维护轮询请求地址、方法、Content-Type、请求头、任务 ID 路径、状态路径、成功/失败状态值、间隔、超时和可选独立返回格式
- AI 配置页提供配置名称、模型快照、文档地址和文档信息字段，提交到 `POST /api/image-model-configs/ai-generate`；生成成功后把返回配置插入模型库列表并关闭 Dialog。该配置默认未启用且没有密钥，用户需要回到基础配置补充密钥后才能启用
- 编辑已有模型时不允许进入 AI 配置页，避免把“生成新配置”误解为覆盖当前配置
- 维护固定单条辅助模型配置，辅助模型表单提供“请求地址”完整 endpoint 字段和“启用辅助模型” Switch；开关切换时立即保存启停状态，左侧状态显示为“在线”或“关闭”
- 辅助模型支持 OpenAI 模式和 Claude 模式
- 辅助模型请求地址字段提交为 `url`，必须填写第三方或官方接口的完整请求 endpoint；后端不会基于模式自动拼接路径
- 以“模型库优先、表单按需弹窗、辅助模型右侧维护”的结构组织配置工作流
- 模型库在桌面端按卡片网格展示，一行最多 3 个配置项
- 模型配置项展示配置名称、请求地址或模型快照、provider 类型、交付方式和启用状态；启用 Switch 放在配置项内部，切换时调用后端专用启停接口
- 模型配置项右侧提供编辑和删除按钮；启用状态用低调色点、边框和行内 Switch 表达，不额外展开说明文案
- 暂无模型配置时只展示透明化空状态标题，不展示额外说明

### 生图页面

生图页面负责：

- 进入页面时刷新生图模型配置列表
- 在创建生图任务按钮左侧选择启用的生图模型配置
- 输入提示词
- 点击按钮调用提示词优化
- 创建生图任务
- 展示任务状态和生成结果
- 创建任务后前端轮询 `GET /api/image-jobs/:id`，直到任务不再处于 `queued` / `running`；轮询窗口最长 5 分钟；如果轮询返回“生图任务不存在”，表示任务失败后端已删除记录，前端提示失败并解除生成锁
- 前端同一时间只允许一个生图任务占用生成通道；任务创建中或处于 `queued` / `running` 时禁用提示词优化与创建生图任务按钮，避免连续点击重复提交
- 页面初始加载历史任务时，如果存在仍处于 `queued` / `running` 的任务，会恢复到任务预览并继续轮询
- 生图加载态在任务预览画布内展示更大的旋转核心、模型/尺寸/分辨率/数量摘要和已等待时间；不展示进度条，也不在加载核心下方展示“生成中”“SYNCING”标签或“正在生成画面”文案
- 任务失败时不进入历史列表；后端删除失败任务记录，前端清空任务预览并通过 Toast 提示“生图失败，未保存历史记录”
- 以“创作”和“任务预览”双栏为主结构；窄屏下自然上下排列
- 桌面端创作列与任务预览列按约 3.5:6.5 分配宽度，任务预览优先获得更多横向空间
- 创作顶部参考图上限来自当前模型 `httpConfig.request.body.referenceImages.maxCount`，默认 16；`mode = none` 时隐藏上传入口，仅保留数量计数
- 尺寸、分辨率和数量位于提示词上方，参数区一行最多放 2 个组件，说明文字位于字段标题右侧
- 尺寸和分辨率下拉优先使用当前模型请求体参数配置里的 `options`；前端展示 `label` 并提交该项目语义值，后端再转换为第三方 API `value`。缺少配置时回退到内置 `auto/1:1/4:3/3:4/16:9/9:16` 与 `0.5k/1k/2k/4k`。
- 数量下拉由当前模型 `quantity.enabled/min/max/defaultValue` 生成；未配置上限时默认 3，`enabled = false` 时只保留默认值 1。
- 优化提示词按钮位于提示词标题右侧，提示词文本域保持更高的创作空间
- 提示词优化成功后直接用后端返回的 `optimizedPrompt` 替换当前文本域内容，不在下方额外展示优化结果卡
- 优化提示词请求进行中时，创建生图任务和失败重试入口都置灰禁用，不显示创建任务 loading 动效；优化失败或结束后恢复；仅创建任务请求进行中时显示 loading
- 预览区域根据 `aspectRatio` 调整容器比例，避免生成结果加载前后布局跳动；`自适应` 使用稳定方形预览占位
- 任务预览画布只保留一层预览容器，不再额外包裹外层边框面板；桌面端预览画布保持更大的最小高度
- 任务返回多张 `imageUrls` 时，任务预览区展示缩略图切换条并在底部显示当前图片序号
- 任务预览中的生成图片支持点击打开居中大图 Dialog，Dialog 只展示图片本体，不显示标题、描述或内部滚动条；图片区域使用接近整屏的宽高并通过 `object-contain` 适配横图和竖图
- 任务预览底部保留创建时间、任务状态、模型配置名称；多图任务额外显示当前图片序号

### 历史页面

历史页面负责：

- 展示后端 `GET /api/image-jobs` 返回的持久化生图任务
- 使用图片缩略图和模型配置名称组成卡片式列表，不使用表格或单行列表
- 历史项 hover 时提供边框、背景和轻微位移反馈
- 历史项右侧提供删除按钮；删除按钮与打开详情的点击区域分离，触发 `DELETE /api/image-jobs/:id` 硬删除任务记录和本地图片文件，删除中显示 loading 并暂时禁用其它删除按钮
- 点击历史项后打开居中 Dialog 展示图片、提示词、模型配置、尺寸、分辨率、数量、创建时间和状态，不展示 provider 来源类型，不在页面右侧常驻详情区
- 历史列表和历史详情中的创建时间显示到年月日时分，不展示秒
- 删除当前打开的历史项后，前端需要关闭详情 Dialog、大图 Dialog，并从历史列表和任务预览状态中移除该任务
- 历史详情中的图片支持点击打开居中大图 Dialog，Dialog 只展示图片本体，不显示标题、描述或内部滚动条，并使用接近整屏的宽高
- 历史任务返回多张 `imageUrls` 时，详情 Dialog 内展示缩略图切换条，并记录当前查看图片序号
- 暂无历史时只展示透明化空状态标题，不展示额外说明
- 进入历史页和页面初始加载时会刷新后端历史列表，刷新网页后历史仍保留

### 识图页面

识图页面负责：

- 通过左侧导航“识图”进入，路由为 `#/recognize`
- 上传单张图片进行无持久化图片理解；前端限制图片类型为 `image/*`，单图最大 20MB
- 识图使用配置页的固定辅助模型配置，不提供单独模型库、不保存识图记录、不进入历史列表
- 提供六个快捷提示词：万物识别、商品标题、五点描述、属性分析、OCR提取、元素提取；点击后直接回填可编辑提问文本域
- “元素提取”用于把图片中的主体、场景、构图、色彩、光影、材质、风格和关键细节整理成可直接复制到生图模型的相似图片提示词，并附带负面提示词
- 点击“开始分析”调用 `POST /api/image/recognize`，请求体包含 `imageDataUrl` 与 `prompt`
- 辅助模型未启用、缺少模型名、请求地址或密钥时，页面禁用分析按钮并提示用户去配置页补齐；未上传图片、提示词为空或正在分析时同样禁用“开始分析”
- “开始分析”禁用态必须使用明显的弱化背景、边框和文字颜色，不能只依赖默认透明度
- 页面采用左侧操作面板与右侧分析结果面板；桌面端列宽与生图页“创作/任务预览”保持一致，按约 3.5:6.5 分配
- 左侧操作面板内部允许在内容超高时滚动，但滚动条默认保持透明，仅在 hover 或 focus-within 时显现，避免刷新或切换到识图页首帧出现原生滚动条闪烁
- 右侧结果区域支持滚动查看长文本和一键复制；模型返回的 Markdown 结果需要渲染为标题、列表、表格、引用、代码块等结构化内容，不能用 `<pre>` 原样显示

## 前端约定

- 基础控件优先使用 `apps/web/src/components/ui` 下的 shadcn 组件
- 图标优先使用 `lucide-react`
- API 调用集中在 `apps/web/src/lib/api.ts`
- 页面组件拆分在 `apps/web/src/pages`：`generate-page.tsx`、`history-page.tsx`、`image-recognition-page.tsx`、`settings-page.tsx`
- `App.tsx` 只保留全局状态、API handler、侧边栏和页面切换容器
- `App.tsx` 负责解析 hash 路由并同步导航状态；页面切换不得只依赖内存中的 React state
- 全局提示工具位于 `apps/web/src/lib/toast.ts`，渲染组件为 `apps/web/src/components/global-toast.tsx`
- Toast 支持 `success` 绿色、`warning` 黄色、`error` 红色、`info` 灰色四种状态，统一从页面顶部弹出；显示和关闭都必须有显式 enter/exit 动画状态，关闭时先播放退出动画再移除节点
- 全局动效工具类集中维护在 `apps/web/src/index.css`，页面和组件只挂载 `motion-*` class，不在业务代码中分散定义动画
- shared 类型从 `@ai-image-codexu/shared` 引入
- 不在前端保存或展示原始 API key

## 本地开发

Web 默认地址：

```text
http://127.0.0.1:3008/
```

API 默认地址由 `VITE_API_BASE_URL` 控制，未配置时前端默认请求同源代理：

```text
/api
```

开发环境 Vite 将 `/api` 代理到 `http://localhost:3007`，用于让后端返回的 `/api/images/*path` 图片地址在前端开发服务器下正常加载。
